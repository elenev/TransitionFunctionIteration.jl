Core workflow

TransitionFunctionIteration.solve_and_simulate — Function
solve_and_simulate(model; setup_kwargs=(;), execute_kwargs=(;), simulate_kwargs=(;),
                   irf_kwargs=(;), run_simulate=true, run_irf=true)

Convenience wrapper: calls main_setup, main_execute!, simulate, and simulate_irf in sequence. Returns a NamedTuple (; obj, stv, simseries, errs, stats, errstats, irf).

Set run_simulate=false to stop after solving; run_irf=false to skip IRF computation.

source
TransitionFunctionIteration.main_setup — Function
main_setup(model; mode=AnalyticalSteadyStateMode(), grids=nothing, check_steadystate=true)
main_setup(model, initobj; ...)

Assemble a ModelSolution for model, computing the steady state, building grids, and constructing initial interpolants. Returns (obj, stv) where obj::ModelSolution is passed to main_execute! and stv::SteadyState holds the steady-state description.

Pass initobj to warm-start from a previously solved solution (e.g., when re-solving after a parameter change).

source
TransitionFunctionIteration.main_execute! — Function
main_execute!(obj; maxiter=100, tol=-5, damp=0.5, npasses=2, solmethod=TFIMethod(),
              damping=:damped_iterate, logging=ITERATIONFAILED, track_history=nothing,
              multithreaded=nothing)

Iterate policy and value functions of obj to convergence.

Solves equilibrium conditions at every grid point, damps the value function update, and repeats until log₁₀(max_distance) < tol or maxiter is reached.

  • tol: convergence threshold as log₁₀ distance (-5 means 1e-5)
  • damp: damping weight in [0,1], applied to value and transition functions (0 = full update, 1 = no update)
  • damping: what damp weights against. :damped_iterate (default): the current damped iterate, x_{t+1} = damp*x_t + (1-damp)*T(x_t) (standard relaxation; damps oscillations of the solution map, distances are fixed-point residuals). :previous_solve: the previous iteration's raw solve, x_{t+1} = damp*T(x_{t-1}) + (1-damp)*T(x_t), as in the MATLAB implementation (mainexecuteupdate.m); a period-2 oscillation of T persists under this rule.
  • npasses: revisit passes for grid points where the solver failed on the first pass
  • solmethod: TFIMethod() (default) or STPFIMethod(), controls whether to precompute expectations (Elenev and Landvoigt) or to add transition functions to the system (Cao et al)
  • multithreaded: nothing (default) threads over grid points when more than one thread is available and the problem is large enough; true/false forces the choice
  • logging: minimum LogLevel to display (COMPLETE suppresses iteration logs)
  • track_history: nothing (default) or (fct_sym, var_names) where fct_sym is :Vfct or :Tfct and var_names is a tuple of variable name Symbols. When set, returns a StructVector of per-iteration snapshots, one entry per iteration, each a NamedTuple of full-grid arrays for the requested variables.

Returns a NamedTuple with convergence info and, when track_history is set, a history StructVector field.

Model interface (stubs)

These functions have default implementations that throw MethodNotImplementedError. Model packages must add methods dispatching on their AbstractModel subtype.

TransitionFunctionIteration.calc_eqm — Function
calc_eqm(state, policy, mdl, np, mode)

Compute equilibrium conditions at state given policy. Interface stub – model packages must add methods dispatching on their AbstractModel subtype.

Expected return: depends on the evaluation mode:

  • in SolveMode: a NamedTuple with fields fx (residuals)
  • in IterateMode: a NamedTuple with fields trans (next-period endogenous state values for each realization of exogenous state), and vals (this-period values of Vfct variables)
  • in SimulateMode: a NamedTuple with fields trans (same as in IterateMode) and simvars (value outputs and extra simulation variables in SimulateMode).

compute_next_period_values(next, model, mode) -> NextPeriod

Compute next-period auxiliary quantities given next-period state next. Interface stub – model packages must add methods dispatching on their AbstractModel subtype.

Return a NextPeriod(; expectations, continuations) where:

  • expectations: probability-weighted scalars (averaged by compute_expectations)
  • continuations: per-state raw values (stacked into an SVector across exogenous states)

TransitionFunctionIteration.steadystate_system — Function
steadystate_system(model, mode) -> (SteadyState, Bool)

Provides an alternative to calc_eqm for the model equations that characterize the steady state. This is useful when the steady state can be characterized by a smaller system of equations.

Expected return: depends on the evaluation mode:

  • in SolveMode: a vector resid of residuals for the steady state system of equations, given a guess for the steady state values.
  • in IterateMode: a tuple of (resid, stv) where resid is the same as in SolveMode and stv is a SteadyState object

containing the steady state values implied by the guess.

source
TransitionFunctionIteration.augment_simulation — Function
augment_simulation(run, model) -> NamedTuple or nothing

Compute extra variables for one simulation run after simulate() finishes.

run is a Vector of T NamedTuples (one period per element). Return a NamedTuple of vectors, one per new variable. A vector of length T - d is a variable that needs d periods of history (d = 0: a variable of each period; d = 1: a variable of consecutive periods, such as a one-period return). It is aligned with the last T - d periods of run, and the first d periods are NaN.

run covers context_periods periods followed by the output periods (see simulate); the context periods are dropped after augmentation. Declare the largest d of any returned variable in dynamic_depth(model) so that the default context_periods leaves no NaN in the output.

The default returns nothing (no augmentation).

source
TransitionFunctionIteration.dynamic_depth — Function
dynamic_depth(model) -> Int

The largest number of periods of history d (the vector length is T - d) of any variable returned by augment_simulation(run, model). It is the default of simulate's context_periods and simulate_irf's hold_periods. The default is 0.

source
TransitionFunctionIteration.augment_errors — Function
augment_errors(obj, state, out, trans) -> (scalar_nt, vector_nt)

Compute extra convergence/consistency diagnostics for one state, on top of the standard equation (fx) and transition (transerr) residuals calc_result always computes.

  • obj: the solved ModelSolution – gives access to obj.Vfct, obj.Tfct, obj.Pfct, obj.model, obj.exogenv, etc., for models that want to interpolate something at state (or elsewhere) themselves. None of these are evaluated automatically by this hook – only whatever a model's own override explicitly calls – so models that don't override augment_errors pay no extra interpolation cost.
  • state: the point calc_result is currently evaluating.
  • out: calc_eqm's own result at state (a NamedTuple with fx, trans, and vals/simvars – the same object calc_result builds fx_nt/transerr from). A returned scalar_nt field name that collides with an existing fx name REPLACES it (later merge wins) rather than erroring – useful for a model that wants to rescale/transform an existing residual, but a footgun if the collision is accidental.
  • trans: obj.Tfct(state), the interpolated transition at state – already computed by the caller regardless (needed to forecast next-period expectations), so it costs nothing extra to pass along even though it's the same kind of "interpolate this yourself" ingredient as obj.Vfct/obj.Pfct would be.

Returns (scalar_nt, vector_nt):

  • scalar_nt: a NamedTuple of scalars, merged into the per-state equation-error output.
  • vector_nt: a NamedTuple of per-next-exogenous-state vectors (same shape as transerr – indexable by next exogenous state index), merged into transerr and resolved the same way downstream (merge_error picks out the realized next state once it's known in simulate()'s loop) – no separate processing needed.

The default returns (;), (;) – no extra measures, no extra interpolation calls.

Solution types

TransitionFunctionIteration.ModelSolution — Type
ModelSolution(; model, exogenv, ssg, Pfct, Vfct)

Assembled solution container for an economic model.

  • model: user-supplied AbstractModel instance (economics logic)
  • exogenv: Exogenv for the Markov exogenous process
  • ssg: combined StateSpaceGrid (exogenous + endogenous axes)
  • Pfct: policy function Interpolant
  • Vfct: value function Interpolant
  • Tfct: transition function Interpolant
  • Ffct: forecasting function Interpolant, or nothing (default) if the model has none. Forecasting values are current-period choices that next period's expectations depend on beyond the next-period state (e.g. the portfolio entering a next-period consumption stage). Unlike Vfct, Ffct is evaluated at the current state; its values are attached to every next-period point by forecast_next. See forecasts_from_policy.
source
TransitionFunctionIteration.SteadyState — Type
SteadyState(; model, exog, endog, values, guess)

Steady-state description returned by steadystate. Holds model-specific values at the non-stochastic steady state and serves as the starting point for main_setup.

  • model: the AbstractModel instance
  • exog: exogenous state at the steady state (e.g., (A=1.0,))
  • endog: endogenous state at the steady state (e.g., (K=3.2,))
  • values: additional reported values (e.g., (C=0.8,))
  • guess: initial policy guess for the solver
source
TransitionFunctionIteration.NextPeriod — Type
NextPeriod(; expectations, continuations, prnext=SVector{1}(1.0))

Container for next-period information returned by compute_next_period_values.

  • expectations: probability-weighted averages (e.g., E[β u′(C′)]); scalar for a given grid point
  • continuations: per-exogenous-state raw values (e.g., capital payoff each state); stacked by compute_expectations into an exnpt-length vector
  • prnext: transition probability vector (default [1.0] for a single state, overridden by Exogenv)

Steady-state modes

TransitionFunctionIteration.AnalyticalSteadyStateMode — Type
AnalyticalSteadyStateMode <: SteadyStateMode

Dispatch tag: steady state is computed by an analytic formula in steadystate(model, ::AnalyticalSteadyStateMode). To use this, implement a method for steadystate dispatching on your AbstractModel subtype and AnalyticalSteadyStateMode().

source
TransitionFunctionIteration.FixedPointSteadyStateMode — Type
FixedPointSteadyStateMode{P<:NamedTuple, T<:NamedTuple, E<:AbstractExogenv, G<:NamedTuple} <: SteadyStateMode

Dispatch tag: steady state is found by iterating on the dynamic model equations and (constant) law of motion for endogenous variables with a starting guess for policy and transition functions."

  • policies: NamedTuple of policy function values at the steady state (e.g., (C = 0.8,))
  • transitions: NamedTuple of transition function values at the steady state (e.g., (K = 3.2,))
  • exogenv: Exogenv representing the exogenous environment at the steady state. Can also be a NamedTuple of exogenous variable values (e.g., (A = 1.0,)), which will be converted to a degenerate Exogenv with a single point.
  • eqmvalguesses (keyword, default empty): guesses for Vfct variables that vals_from_policy cannot compute because they depend on expectations (e.g. a value function). They become extra unknowns; their residuals are the guess minus the value calc_eqm returns in vals.
source
TransitionFunctionIteration.SystemSteadyStateMode — Type
SystemSteadyStateMode{S<:NamedTuple, B<:NamedTuple} <: SteadyStateMode

Dispatch tag: steady state is found by solving a steadystate specific nonlinear system (e.g., system of equilibrium conditions). Must implement steadystate_system(guess, model, mode) which returns the system residuals given a guess for the steady state values.

TransitionFunctionIteration.StateSpaceGrid — Type
StateSpaceGrid(; name=grid, ...)
StateSpaceGrid(exogenv, endog_grids::NamedTuple)

Multidimensional state space grid with named axes.

Each keyword argument defines one axis. Scalar-valued fields are marked as singletons — they are stored in the grid but excluded from interpolation axes. The second constructor prepends the exogenous state indices from exogenv as the :exst axis.

source
TransitionFunctionIteration.Interpolant — Type
Interpolant(ssg, returnvals::NamedTuple)
Interpolant(ssg, returnvals::StructArray)

Gridded interpolation of multiple named functions over a StateSpaceGrid.

The NamedTuple constructor initializes every grid point to the same constant values. The StructArray constructor uses per-point values; its shape must match dims(ssg).

Uses Gridded(Linear()) for endogenous dimensions and NoInterp() for :exst. Extrapolation is Flat() for endogenous axes and Throw() for :exst.

Evaluation

Call the interpolant like a function to evaluate it at a state point or collection:

# Single point -- returns a NamedTuple with one field per output variable
vals = fct((exst=1, K=0.5))
vals = fct(exst=1, K=0.5)          # kwargs form

# Collection -- returns a StructArray
vals = fct(points(ssg))
vals = fct((exst=i, K=k) for (i,k) in zip(states, capitals))

The state NamedTuple may contain any subset of ssg dimensions; singleton dimensions are silently dropped before interpolation. Output field names match varnames(fct).

Exogenous environment

TransitionFunctionIteration.ExogenvAR1 — Function
ExogenvAR1(; ρ=0.0, σ=1.0, μ=0.0, n=3, jensen=false, transform=identity, shock_name=:z)

Construct an Exogenv for a discretized AR(1) process using the Rouwenhorst method.

  • ρ: persistence
  • σ: unconditional standard deviation
  • μ: unconditional mean (in levels before transform)
  • n: number of grid points; n = 1 gives a degenerate process with one point at transform(μ)
  • jensen: if true, uses transform=exp and applies Jensen correction so that the unconditional mean of the transformed process equals exp(μ)
  • shock_volatility: if true, the supplied σ is the volatility of the shock rather than the state, so the function adjusts σ accordingly
  • transform: applied element-wise to the grid (default identity; use exp for log-normal)
  • shock_name: name of the exogenous variable in the state NamedTuple

Impulse responses

TransitionFunctionIteration.simulate_irf — Function
simulate_irf(obj, endogstart; shocks=(;), T=20, N=5_000, seed=100,
             hold_periods=dynamic_depth(obj.model), ...)

Simulate impulse response functions (IRFs) from a solved model obj.

  • endogstart: initial endogenous state, either a NamedTuple of values or a SimulationPanel (in which case the ergodic mean is used)
  • shocks: NamedTuple of forced exogenous paths after the starting period, each an exogenous state index or a vector of indices, e.g. (hike = 5, hike2 = [5, 5]); empty (the default) means one shock per other exogenous state plus the unconditional baseline uncond = Int64[]
  • T: IRF horizon (periods)
  • hold_periods: periods the exogenous state is held at exog_start before the IRF, starting from endogstart with no shock. The endogenous state after them is the IRF's initial state and the held periods supply the history of the variables of augment_simulation, so period 1 of the IRF has no NaN if hold_periods is at least dynamic_depth(obj.model) (the default). The held periods are not part of the output.
  • N: number of Monte Carlo draws for expectation/fan charts
  • seed: random seed for reproducibility

Returns an IRFResult with mean and standard-deviation paths for each shock, and its Provenance{IRFSettings}.

source
TransitionFunctionIteration.IRFResult — Type
IRFResult

Container for impulse-response function results returned by simulate_irf.

  • means: NamedTuple of StructArrays (one per shock) of per-period mean paths
  • stdevs: same structure, per-period standard deviations across simulation draws
  • other_stats: additional user-requested statistics (see other_stats kwarg of simulate_irf)
  • paths: per-draw raw simulation paths (non-empty only when path_vars is set)
  • provenance: the IRF's Provenance{IRFSettings}, or nothing

Access individual shock paths with irf.means.shock_name.varname.

An IRFResult is a table of its statistics (__shock, __stat, __period, then one column per variable); irf_paths(irf) is the table of raw paths. IRFResult(stats_table) and IRFResult(stats_table, paths_table) restore it from these tables, e.g. two parquet files.

TransitionFunctionIteration.ImpulseMoment — Type
ImpulseMoment(; var, shock, period, stat=:mean, transformation=Transformations.Level,

A point on an impulse response: stat of var under shock, period periods into the IRF (period indexes the IRF lines, so it is the __period of the IRF table; 1 is the starting period).

TransitionFunctionIteration.CalculatedMoment — Type
CalculatedMoment(f, inputs; transformation=Transformations.Level(),
                 compare_transformation=Transformations.Level())

A function of other moments: f(nt) where nt is a NamedTuple with the keys of inputs and, as values, the inputs read from the same economy with their own transformations (their compare_transformations are ignored: a comparison across economies is made once, on the result). inputs is a NamedTuple of moments, which may themselves be CalculatedMoments.

source
TransitionFunctionIteration.@CalculatedMoment — Macro
@CalculatedMoment expression
@CalculatedMoment names expression

A CalculatedMoment written as an expression of moments. Every function call in the expression is evaluated as lifted(f, args...): the plain call if no argument is a moment (so SimulationMoment(:C) is still a moment), otherwise a CalculatedMoment of the moment arguments, with the other arguments as constants. Any function of numbers works, operators included, and the result may be used in further expressions.

ols = @CalculatedMoment cor_C_Y * sd_C / sd_Y    # three moments in scope
@CalculatedMoment sqrt(SimulationMoment(:K; stat = :std)^2 + 2.0)

With names (a NamedTuple or Dict of moments), a bare name that is not a variable in scope is read as names[:name], so @CalculatedMoment moments mean_C / mean_Y refers to named moments directly; a name that is neither is an error. Only calls are lifted: if, &&, broadcasting and anonymous functions are left as they are, and a moment passed as a keyword argument is not lifted.

source

TransitionFunctionIteration.compare_economies — Function

TransitionFunctionIteration.simulate — Function
simulate(obj, stv=nothing; sz=10_000=>12, seed=100, burn=500,
         exog_start=ssidx(obj.exogenv), endog_start=stv.endog,
         context_periods=dynamic_depth(obj.model), report_bounds=true)
simulate(obj, exog_states::AbstractMatrix{<:Integer}; endog_start, burn=0,
         context_periods=dynamic_depth(obj.model), report_bounds=true)

Simulate the solved model along stochastic paths.

The first form draws the exogenous path from seed: sz = N_periods => N_runs output periods and runs, starting from exogenous state exog_start. The second form takes the exogenous path as given: a matrix of exogenous state indices with burn + context_periods + N_periods rows (burn-in, context periods, output periods) and one column per run, whose first row is the starting state.

Returns (simseries, errs), both N_periods × N_runs:

  • simseries: SimulationPanel of state and output variables
  • errs: SimulationErrorPanel of equation and transition errors

Both carry the same Provenance{SimulationSettings}. The first burn periods are simulated but not used for anything. The next context_periods are the history that variables of augment_simulation need (see dynamic_depth): they are augmented and then dropped from the output. A variable that needs more history than context_periods has NaN in its first output periods; with context_periods = 0 nothing is dropped.
